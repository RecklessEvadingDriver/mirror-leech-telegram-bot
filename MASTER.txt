FileHub is a heavily customized production-focused fork of Mirror-Leech-Telegram-Bot.

DO NOT create a separate demo project.

DO NOT rewrite the project from scratch.

DO NOT replace working functionality unnecessarily.

Inspect the existing repository first, understand the current architecture, then incrementally implement the features below using the existing engines, Telegram handlers, MongoDB layer, queue system, downloader/uploaders, FFmpeg functionality, and FileHub platform modules.

## CRITICAL RULES

* No mock data.
* No fake API responses.
* No placeholder buttons.
* No dead UI.
* No fake dashboards.
* No hardcoded test credentials.
* No fake task status.
* No stub features presented as completed.
* Every visible feature must be connected to real application state.
* Every button must perform a real action or clearly be marked unavailable.
* Do not silently break existing MLTB functionality.
* Preserve backwards compatibility wherever practical.
* Do not weaken authentication or authorization.
* Owner-only functionality must remain owner-only unless explicitly redesigned with a safer permission model.
* Never expose secrets in logs, Telegram messages, HTTP responses, exceptions, or dashboards.
* Never disable TLS certificate verification just to make something work.
* Never use `eval()` or equivalent unsafe dynamic execution for user-controlled values.
* Never deserialize attacker-controlled pickle data.
* Never use `shell=True` when an argument-list subprocess call can be used.
* Do not use world-writable filesystem permissions.
* Avoid broad exception swallowing.
* Add timeouts to all external network operations.
* Validate all untrusted input.
* Apply rate limiting where appropriate.
* Keep implementation modular and production-ready.
* Do not claim a feature is complete until it has been integrated and tested.
